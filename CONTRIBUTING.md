# Работа над книгой и кодом

Новая книга находится в `book/`. Текущая программа и незаконченные задачи — в [book/CONTINUE.md](book/CONTINUE.md). Старый курс и корневое приложение пока представляют предыдущую редакцию.

## Изменение главы

1. Прочитайте [редакционные требования](book/editorial/teaching-contract.md) и [карту языка](book/editorial/language-map.md).
2. Меняйте исполняемый код в `book/examples/`, а в рукописи используйте включение исходника. Не исправляйте копию кода только в готовом PDF или HTML.
3. Обновляйте реестр `book/book.json` и ожидаемый вывод вместе с поведением. Для новой конструкции сначала напишите объяснение, затем добавьте её в `book/editorial/syntax-policy.json`.
4. Выполните `python3 book/tools/check.py`. Для изменений вёрстки соберите и проверьте три формата по [инструкции](book/README.md), просмотрите затронутые страницы.
5. В pull request объясните проблему читателя, результат изменения и фактически выполненные проверки. Отдельно отметьте оставшиеся пробелы.

Работайте в отдельной ветке. Не включайте в коммит `.env`, локальные извлечения исходных курсов, кеши и `book/build/`. Готовые издания публикуются как файлы выпуска после редакторской приёмки. До завершения книги отмечайте сборки как предварительные.

Исправление ошибки в старом курсе сопровождайте воспроизводимым примером. Аналогия помогает понять правило, но не заменяет его: указывайте границы образа и не обещайте измеримого ускорения обучения без подтверждения.

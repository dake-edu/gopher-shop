## Подтверждённые проблемы и решения

1. **Учёт заказов отсутствует в просмотренном обработчике.** `services/orders-service/main.go:47–77`: после чтения товара возвращается 201, но записи заказа нет. Новый проект обязан сохранять заказ до успешного ответа; проверка — чтение после перезапуска.
2. **Покупатель задаётся клиентом.** Там же `createOrderRequest.UserID` переносится в ответ; в `routes` нет аутентификации. Для магазина личность определяется проверенной сессией. Тест: подмена идентификатора не даёт оформить заказ от чужого имени.
3. **Цена как float64.** `platform/poststore/post.go:16`. В новой модели сумма — целое число минимальных денежных единиц плюс код валюты; нужны проверки диапазона, количества и правил округления. Значение цены фиксируется в позиции заказа, а не берётся заново при выдаче.
4. **Ограничения HTTP не заданы в обработчике заказов.** Чтение JSON без явного ограничения тела, сервер через `http.ListenAndServe`. Добавить лимиты и осмысленные таймауты, тестировать некорректные и слишком большие запросы. Не выдавать учебный сервер за готовый публичный сервис.
5. **Документированные пробелы тем Go.** `course/lessons/README.md` прямо указывает на забытые массивы и константы. Ввести матрицу: тема → объяснение → упражнение → проверка. Аналогично проверить строки, замыкания, defer, embedding, интерфейсы, generics и конкурентность.
6. **Проверка синтаксиса не равна проверке поведения.** Там же Go-проверка описана через `gofmt -e`; поведенческий запуск описан для Python. Для книги нужны компиляция, запуск обещанного вывода и тесты каждого состояния Go-проекта.
7. **Ошибочный тезис о Compose.** `book_chapters/chapter_21.txt` утверждает, что Compose не перезапустит упавший сервис. Это зависит от restart policy, которая предусмотрена Compose. Исправление опирается на [документацию Docker](https://docs.docker.com/reference/compose-file/services/). Отказ хоста и перезапуск процесса нужно объяснять отдельно.
8. **Неполная навигация.** README блога перечисляет шаги до 29, хотя есть каталоги 30–34. Уточнение: `chapter_01.txt` — вступление, поэтому `chapter_21.txt` соответствует главе 20; само смещение имён файлов ошибкой не является. Собирать оглавление из одного реестра, проверять существование всех контрольных точек.
9. **Слишком категоричные педагогические обещания.** `start.md` обещает, что английский не потребуется, сборки всегда быстрые, а единственная платная часть — домен. Для магазина это неподходящие гарантии. Указать реальные предпосылки; стоимость хостинга и платежей зависит от выбранной среды. Убрать недоказанное объяснение обучения «мышечной памятью» и гарантии времени освоения.
10. **Случайный порядок SQL выдан за ожидаемый.** В `tx.md` вывод `ORDER BY ?` объяснён порядком хранения. Константа не задаёт различий между строками; устойчивый порядок нельзя обещать без подходящего ORDER BY. В новом примере проверять отсутствие требуемой сортировки без обещания случайного порядка. Параметризацию объяснять через разделение SQL и значений, без универсальных утверждений о внутренней реализации драйвера.

## Что сокращаем

Сокращатель ссылок и TCP-чат не станут отдельными обязательными проектами: их идеи перенесём на каталог, обработку событий и выдачу файлов. gRPC и Kubernetes — дополнительные инженерные разборы после работающего магазина. Удаляем повторяющиеся лозунги, избыточные кавычки, обязательные интервью ради терминов и рисунки без учебной функции.

## Углублённая проверка первых тем — 2026-09-10

11. **Ошибка семантики map и получателя-значения.** `book_chapters/chapter_04.txt`, раздел 3.1, утверждает, что добавление в map через копию структуры не изменит оригинальное содержимое. Проверено отдельной программой `research/reproductions/map-value/main.go`: запись через получателя-значение видна исходной структуре, а замена поля map — нет. В Go значение map при копировании продолжает ссылаться на те же данные. Указатель необходим для замены поля исходной структуры, а наличие mutex даёт отдельную причину избегать копирования. Не учить общей формуле «указатель не копируется»: само значение указателя также передаётся копированием.
12. **Слишком общее утверждение о var.** `chapter_03.txt`: «var создает nil map». Это верно для объявления без инициализатора, но не для `var m = make(map[string]string)`. В новой главе показать обе формы и отделить способ объявления от начального значения.
13. **Неточная формулировка constraint.** `course/lessons/go/next.md` называет `Number` «не типом». Объявление создаёт именованный интерфейсный тип с набором типов; такой интерфейс применим как ограничение параметра типа и не используется как обычный тип переменной. Исправить объяснение без отрицания того, что это тип.
14. **Невоспроизводимый фрагмент провала теста.** `test.md` предлагает изменить первое сравнение, но демонстрирует два сообщения об ошибке. Во второй проверке `len(got) != 2` условие остаётся ложным. В новой книге намеренная поломка исполняется инструментом проверки; ожидаемый провал фиксируется в отчёте.
15. **Преждевременные обобщения о производительности.** Первые главы The Gopher Shop обещают невероятную скорость как следствие компиляции. Новая книга не выводит быстродействие приложения из названия языка: оценки производительности появятся рядом с измеряемой задачей и средой.

## Ограничение доступности части курса

В локальном каталоге найдено 43 русских Markdown-файла, в том числе вводные страницы. Сайт описывает курс как 50 уроков (`pkg/modules/articles/pages.go`). Ссылки из intro.md показывают ранние уроки про интернет, установку, первую программу, переменные и функции, которым нет соответствующих локальных Markdown-файлов. Веб-инструмент не открыл эти страницы в этой сессии. Их нельзя считать прочитанными или отсутствующими в опубликованном курсе; полный аудит курса остаётся незавершённым.

16. **Отмена SQL обещана без условия.** `context.md` говорит, что запрос по истечении срока обрывается на стороне базы. [database/sql](https://pkg.go.dev/database/sql) прямо оговаривает: драйвер без поддержки отмены не вернётся до завершения запроса. Учить передаче контекста, но проверять фактические гарантии драйвера; отмена ожидания не доказывает откат уже принятой операции.
17. **XSS сведён к одному типу.** `csrf.md` называет `template.HTML` единственным способом открыть XSS в Go. Это неверное обобщение: безопасность зависит и от других доверенных типов, шаблонов, прямой выдачи HTML и клиентского кода. [html/template](https://pkg.go.dev/html/template) описывает свою модель доверия, а не защиту любого кода приложения.
18. **SameSite и пример img требуют исправления.** В `csrf.md` смешаны разрешённый Lax переход верхнего уровня и запрос изображения. Не использовать `<img>` как пример гарантированной отправки Lax-cookie с другого сайта. Запрет изменения состояния через GET сохраняется; пример атаки должен соответствовать контексту браузера. Перед новой главой проверить по актуальной документации браузеров.
19. **Сравнение по времени описано слишком категорично.** `passwords.md` обещает одинаковое время ответа из трёх наблюдений. Дополнительная проверка dummy-хеша уменьшает очевидное различие веток, но не доказывает постоянное время полного запроса. Сохранять общую ошибку входа и ограничения попыток, не обещать равенство сетевых таймингов.
20. **Копирование объявлено всегда более дешёвым.** `pointers.md` утверждает «копия дешевле и безопаснее». Цена зависит от размера значения, аллокаций, escape analysis и нагрузки; безопасность зависит от разделяемого состояния. Объяснять семантику отдельно от измерений производительности.
